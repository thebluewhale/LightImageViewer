# LightImageViewer PoC 0.3.5

Windows 10/11 x64용 설치 없는 이미지 뷰어입니다. 실행 파일은 `dist/LightImageViewer.exe`이며 .NET을 별도로 설치할 필요가 없습니다. 실행에 필요한 네이티브 구성 요소는 첫 실행 시 Windows 임시 폴더에 자동으로 풀립니다. 관리자 권한은 필요하지 않습니다.

포터블 EXE와 설치 파일은 [GitHub Releases](https://github.com/thebluewhale/LightImageViewer/releases/latest)에서 다운로드할 수 있습니다. 소스 저장소에는 배포 EXE, SDK, 생성된 테스트 이미지와 빌드 결과물을 포함하지 않습니다.

## 포터블 EXE와 설치 파일

두 가지 실행 방식을 제공합니다. 설치 버전에 포함된 프로그램은 포터블 EXE와 동일합니다.

| 파일 | 용도 |
|---|---|
| `dist/LightImageViewer.exe` | 설치 없이 바로 실행하는 기존 포터블 버전 |
| `dist/LightImageViewer-Setup-0.3.5.exe` | 관리자 권한으로 공용 폴더에 설치하는 설치 프로그램 |

설치 완료 화면의 **기본 앱 설정 열기** 버튼을 누르면 Windows 설정으로 이동합니다. 지원되는 Windows 11에서는 LightImageViewer의 기본 앱 페이지를 직접 열고, Windows 10에서는 기본 앱 목록을 엽니다. 목록이 표시되면 LightImageViewer를 검색하세요. 확장자별 최종 기본 앱 선택은 Windows 화면에서 직접 합니다. 버튼을 누르기 전에는 설정을 열지 않으며 무인 설치에서는 실행하지 않습니다.

설치 파일을 실행하면 다음 항목을 구성합니다.

- 설치 위치: `C:\Program Files (x86)\LightImageViewer`
- 시작 메뉴: **LightImageViewer → LightImageViewer** 바로가기
- Windows **설정 → 앱 → 설치된 앱**: LightImageViewer 이름·버전·제거 명령 등록
- Windows **설정 → 앱 → 기본 앱** 및 **연결 프로그램**: 지원하는 27개 이미지 확장자의 후보 앱으로 등록. 기본 앱은 사용자가 선택합니다. 제거하면 앱이 등록한 후보 항목을 정리합니다.
- 설치·제거 시 관리자 권한을 요청합니다. 프로그램과 시작 메뉴 바로가기는 모든 사용자에게 제공되며, 평소 뷰어 실행에는 관리자 권한이 필요하지 않습니다.
- 기존 포터블 EXE와 이미지 파일은 변경하지 않습니다. 이미지의 기본 연결 프로그램은 자동 변경하지 않습니다.

설치 버전을 기본 이미지 뷰어로 지정하려면 **설정 → 앱 → 기본 앱 → LightImageViewer**에서 확장자별 연결을 선택하세요. 또는 이미지 우클릭 → **연결 프로그램 → 다른 앱 선택 → LightImageViewer**를 선택하세요. 이전 0.3.0 설치에서는 후보 등록이 누락되었으므로 0.3.2 설치 파일을 덮어 설치한 뒤 설정 창을 닫았다가 다시 여세요. 설치 버전을 업데이트할 때에는 새 설치 파일을 실행하면 됩니다. 설치 위치와 앱 등록을 재사용하며 사용자 설정은 유지합니다.

### 제거와 설정 파일

Windows **설정 → 앱 → 설치된 앱 → LightImageViewer → 제거**에서 제거합니다. 제거 과정에서 **현재 제거 프로세스 계정의 창 크기·위치 설정과 오류 로그도 삭제할지** 묻습니다.

- **아니요 (기본 선택)**: 설정 유지. 나중에 다시 설치하면 기존 설정을 사용할 수 있습니다.
- **예**: `%LOCALAPPDATA%\LightImageViewer\window.json`과 `error.log` 삭제. 그 폴더 안의 다른 파일은 삭제하지 않습니다.

LightImageViewer의 포터블 버전과 설치 버전은 설정 폴더를 공유하므로, 설정 삭제를 선택하면 포터블 버전의 창 설정도 초기화됩니다. 제거 전에 실행 중인 뷰어를 종료하세요. UAC에서 다른 관리자 계정으로 인증했다면 설정 삭제 대상은 그 관리자 계정이며, 삭제 안내에 실제 경로를 표시합니다. 다른 사용자 계정의 설정은 삭제하지 않습니다. 이전 이름인 ImageViewer의 설정 폴더는 별도로 보존합니다. 프로그램·시작 메뉴 바로가기·설치된 앱 등록은 제거되지만, 별도로 보관한 포터블 EXE와 원본 이미지 파일은 유지됩니다.

자동화된 무인 제거는 기본적으로 설정을 유지합니다. 설정 삭제를 명시하려면 설치 폴더의 `unins000.exe`에 `/VERYSILENT /NORESTART /DELETESETTINGS=1`을 전달합니다. 일반적인 사용에서는 Windows 설정의 제거 버튼을 사용하면 됩니다.

## 사용하기

1. `dist/LightImageViewer.exe`를 더블클릭합니다.
2. **파일 열기** 버튼 또는 **Ctrl+O**로 이미지를 선택합니다. 탐색기에서 파일을 창에 끌어 놓아도 됩니다.
3. **→ / ↓ / Page Down**은 다음, **← / ↑ / Page Up**은 이전 이미지입니다.
4. **F1**은 도움말과 포함된 라이브러리 라이선스를 보여 줍니다.

### 확대와 탐색

| 동작 | 마우스 / 메뉴바 | 키보드 |
|---|---|---|
| 이전·다음 이미지 | 휠 위: 이전 / 휠 아래: 다음 | ← / → 등 탐색 키 |
| 확대·축소 | Ctrl+휠 위·아래 / +·− 아이콘 | + / − |
| 이미지 이동 | 확대된 이미지를 왼쪽 버튼으로 드래그 | — |
| 원본 크기 | 1:1 아이콘 | 1 |
| 창에 맞추기 | 사각형 안 화살표 아이콘 | F |
| 전체화면 | 네 방향 화살표 아이콘 | F11 |
| 전체화면 종료 | — | Esc / F11 |
| 첫 이미지 / 마지막 이미지 | — | Home / End |
| 애니메이션 재생·정지 | 재생·정지 아이콘 | Space |
| TIFF 이전·다음 페이지 | 페이지 좌우 화살표 | [ / ] |

일반 휠은 이미지 파일을 이전·다음으로 넘깁니다. Ctrl+휠 확대는 마우스 포인터가 가리키는 위치를 기준으로 합니다. 확대율은 1~3200%이며, 드래그는 이미지 가장자리까지만 이동합니다. 메뉴바 확대·축소는 화면 중심을 기준으로 합니다. 원본 크기와 창 맞춤을 선택하면 이미지를 다시 가운데로 정렬합니다. 새 파일 또는 TIFF 페이지를 열면 창 맞춤으로 시작합니다.

전체화면에서는 제목 표시줄·메뉴바·상태 표시줄을 숨기고 현재 모니터 전체에 이미지를 맞춥니다. Esc를 누르면 이전 창 크기·위치·최대화 상태로 복귀합니다. 전체화면에서도 휠, 드래그, 키보드 탐색과 Space를 사용할 수 있습니다.

이미지 파일을 더블클릭해서 열려면, 이미지 파일 우클릭 → **연결 프로그램 → 다른 앱 선택**에서 `LightImageViewer.exe`를 찾아 **항상** 사용하도록 지정하세요. Windows 버전에 따라 메뉴 이름이 조금 다를 수 있습니다. `.png`, `.jpg`, `.jpeg`, `.webp` 등 사용하는 확장자마다 한 번씩 지정해야 합니다. 연결한 뒤에는 EXE의 위치를 유지하세요. 이 프로그램은 Windows 기본 앱 설정을 자동 변경하지 않습니다.

명령줄에서도 이미지 경로 하나를 받을 수 있습니다. 경로에 공백이 있다면 따옴표로 감싸세요.

```powershell
& 'D:\Projects\ImageViewer\dist\LightImageViewer.exe' 'D:\사진 폴더\사진 1.webp'
```

## 구현한 동작

- ANI, AVIF, BMP, CUR, EMF, GIF, HDP, ICNS, ICO, JFIF, JPE, JPEG, JPG, PBM, PCX, PGM, PNG, PPM, PSB, PSD, RAS, TGA, TIF, TIFF, WBMP, WebP, WMF 지원. 확장자 대소문자를 구분하지 않습니다.
- Windows 기본 제목 표시줄: 파일 이름, 최소화, 최대화/복원, 닫기.
- 하단 왼쪽: `현재 번호/전체 개수`, 방향 보정 후 원본 픽셀 크기, 디스크 파일 크기. `1 MB = 1,000,000 bytes`이며 용량 위에 마우스를 올리면 정확한 바이트 수가 나옵니다.
- 현재 파일과 **같은 폴더만** 탐색하고 하위 폴더와 지원하지 않는 파일은 제외합니다.
- Windows 자연 정렬 사용: `1.png → 2.png → 10.png`.
- 마지막에서 다음은 처음, 처음에서 이전은 마지막. 파일이 하나라면 같은 파일을 유지합니다.
- EXIF 방향 1~8(회전과 반전)을 적용합니다.
- 투명한 부분에는 체크무늬 배경을 표시합니다.
- 큰 이미지는 종횡비를 유지하며 창에 맞추고, 작은 이미지는 화면의 실제 픽셀 기준 1:1로 표시합니다. 창 크기와 모니터 배율 변경을 반영합니다.
- 키를 빠르게 반복 입력하면 선택 인덱스는 모두 반영하고, 마지막 요청의 이미지만 표시합니다. 일반 이미지 로딩·원본 읽기·주변 이미지 미리 읽기는 한 작업씩 처리합니다. 애니메이션은 별도 작업에서 다음 프레임 하나를 미리 읽습니다.
- 손상되거나 삭제된 파일, 권한 문제, 지원하지 않는 파일, 메모리 부족은 오류 화면으로 안내합니다. 폴더 탐색 중 읽기에 실패해도 방향키로 계속 이동할 수 있습니다.
- 정지 이미지는 읽은 뒤 파일을 닫습니다. 애니메이션은 재생 중 스트림을 유지하되 다른 프로그램의 이동·삭제를 허용합니다. 원본 파일이 변경된 경우 캐시를 재검증합니다.
- 여러 파일을 드롭하면 지원하는 첫 번째 이미지 파일을 엽니다.

## PoC 범위

- ANI는 RIFF ACON의 ICO/CUR 프레임, 재생 순서(`seq`), 프레임별 시간(`rate`)을 읽어 반복 재생합니다. Space와 재생·정지 버튼을 사용합니다. 아이콘 프레임 방식의 ANI를 지원하며, 프레임 최대 4096×4096, 4096개 프레임·65536개 재생 단계로 제한합니다. 오래된 raw bitmap ANI는 지원하지 않습니다.
- PSD/PSB는 파일에 저장된 합성 이미지 한 장을 표시합니다. 레이어 편집·개별 레이어 보기·재합성은 하지 않습니다. 합성 이미지가 없는 파일은 Photoshop의 **호환성 최대화** 옵션으로 다시 저장해야 합니다.
- ICNS는 가장 큰 PNG/JPEG 2000 또는 클래식 32비트 RGB/RLE 표현과 투명도 마스크를 사용합니다. 오래된 1/4/8비트 인덱스 아이콘만 들어 있는 ICNS는 지원하지 않습니다. ICO/CUR는 대표 이미지 하나를 표시합니다.
- EMF/WMF는 Windows에서 래스터화해 표시합니다. AVIF는 정지 이미지/첫 프레임을 표시합니다. HDP는 Windows 기본 JPEG XR(WIC) 디코더를 사용합니다. HDR·16/32비트 채널 이미지는 일반 화면용 8비트 데이터로 표시하며 HDR 출력·레이어 편집은 범위에 포함하지 않습니다.

- GIF와 애니메이션 WebP는 자동 재생하며 파일에 지정된 프레임 시간과 반복 횟수를 반영합니다. 10ms 이하의 프레임 지연은 100ms로 보정합니다. 재생·정지 버튼과 Space를 지원하고 창을 최소화하면 프레임 진행을 쉽니다. GIF 배경 복원은 브라우저 계열 디코더와 같이 투명 배경으로 처리합니다.
- 다중 페이지 TIFF는 첫 페이지부터 표시하며 페이지 버튼 또는 [ / ]로 이동합니다. 방향키와 Home/End는 계속 파일 간 이동에 사용합니다. TIFF 페이지 이동은 양 끝에서 멈춥니다.
- 파일당 최대 **8 GiB**, 원본 최대 **10억 픽셀**을 허용합니다. 화면용 데이터는 **3,200만 픽셀·긴 변 16,384px 이하**로 제한합니다. 큰 이미지의 1:1 보기는 원본 좌표와 확대율을 유지하지만 세부 픽셀은 축소된 표시 데이터를 사용합니다. 하단 해상도는 원본 기준이며, 확대용 데이터도 제한되면 상태 표시줄에 안내합니다. 실제 처리 가능 여부는 형식, 메모리와 임시 디스크 여유에 따라 달라집니다.
- 폴더 목록은 파일을 열 때 구성합니다. 외부에서 추가하거나 이름을 바꾼 파일을 반영하려면 Ctrl+O 또는 드래그 앤 드롭으로 파일을 다시 여세요. 탐색 중 삭제된 파일은 오류 항목으로 유지됩니다.
- 이미지 파일을 새로 더블클릭하면 새 창을 엽니다.
- 창 위치·크기·최대화 상태를 `%LOCALAPPDATA%\LightImageViewer\window.json`에 저장합니다. 전체화면에서 닫아도 전체화면 전의 창 상태를 기억합니다. 저장 파일이 손상되면 기본 창으로 시작하고, 사라진 모니터의 위치는 사용 가능한 화면으로 옮깁니다.
- 오류 기록은 `%LOCALAPPDATA%\LightImageViewer\error.log`에 남깁니다. 이미지 원본은 수정하지 않습니다.

## 로딩 성능 개선

- **빈 화면 없는 이미지 전환**: 다음 이미지가 준비될 때까지 이전 이미지와 확대·이동 상태, 제목·해상도·파일 크기를 유지합니다. 새 이미지와 표시 정보는 함께 교체하고 창 맞춤으로 전환합니다. 탐색 인덱스는 선택한 파일을 즉시 반영합니다. 전환 중 이전 애니메이션은 마지막 프레임으로 멈추며, 이전 이미지의 원본 재읽기·재생·TIFF 페이지 조작은 잠시 제한합니다. 읽기에 실패하면 해당 파일의 오류를 표시하며 다른 이미지로 계속 이동할 수 있습니다.

- **로딩 안내 지연 표시**: 파일 선택 후 300ms 이내에 로딩이 끝나면 로딩 문구를 표시하지 않습니다. 300ms가 지나도 로딩 중이면 하단 상태를 표시합니다. 아직 표시한 이미지가 없는 첫 로딩에서는 중앙 안내도 표시합니다. 파일 용량이나 해상도 대신 실제 대기 시간을 기준으로 하며, 로딩 완료·실패·다른 파일 이동·창 닫기 시 이전 안내 예약을 취소합니다.

- **대형 파일 자원 제한**: 큰 정지 이미지와 추가 형식은 Magick.NET의 디스크 기반 픽셀 캐시를 활용합니다(픽셀 캐시 메모리 256 MiB, 임시 디스크 8 GiB, 디코더 작업 스레드 2개). 이는 프로그램 전체 메모리의 상한은 아닙니다. Windows 임시 폴더에 여유 공간이 필요하며 디코딩 종료 시 캐시를 해제합니다. TIFF/HDP는 Windows 디코더 경로를 사용합니다. GIF/WebP 재생은 프레임당 3,200만 픽셀까지이며 이를 넘으면 정지 미리보기와 재생 실패 안내를 표시합니다.

- **선택한 파일 먼저 표시**: 폴더 열거·정렬을 백그라운드에서 진행하는 동안 선택한 파일을 먼저 읽습니다. 폴더 목록 준비 중에는 `1/…`로 표시합니다.
- **큰 이미지 미리보기**: 초기 로딩은 화면 크기에 맞춘 1536~4096px 미리보기를 사용합니다. JPEG 등의 코덱 축소 디코딩을 활용하고, 확대 시 필요한 원본을 비동기로 읽어 교체합니다. 하단 해상도는 항상 원본 기준입니다. PNG 등은 형식에 따라 내부적으로 전체 디코딩이 필요할 수 있습니다.
- **앞뒤 이미지 미리 읽기**: 현재 이미지가 안정적으로 표시되면 앞뒤 파일의 미리보기를 읽습니다. 새 입력이 오면 이전 미리 읽기 요청을 취소합니다.
- **메모리 캐시**: 이미지 캐시는 최대 128 MiB, 12개 항목이며 오래 사용하지 않은 항목부터 비웁니다. 큰 원본은 캐시에 중복 보관하지 않습니다. 파일 크기와 수정 시각을 검사해 오래된 결과 사용을 피합니다.
- **애니메이션 메모리 제한**: 모든 프레임을 한꺼번에 만들지 않습니다. 현재·다음 프레임과 합성 버퍼를 유지하고, 전체가 64 MiB·512프레임 이내일 때만 재사용 캐시를 채웁니다.
- **폴더 정렬 비용 절감**: 파일 이름을 한 번 추출해 자연 정렬하고, 목록을 만드는 동안 개별 이미지의 해상도나 EXIF를 읽지 않습니다.

캐시 제한은 디코딩 임시 버퍼나 WPF/GPU 메모리를 포함한 프로세스 전체 제한은 아닙니다. 큰 이미지의 실제 메모리 사용량은 더 클 수 있습니다.

## 개발 및 빌드

기술 구성: C# / .NET 10 / WPF, SkiaSharp 4.157.0 이미지 디코더, Windows WIC TIFF/HDP 디코더, Magick.NET-Q8-x64 15.1.0 추가 형식 디코더, ANI/ICNS 컨테이너 처리.

프로젝트 내부 `.tools/dotnet`에 준비한 SDK 또는 시스템에 설치된 .NET SDK 10.0.404를 사용합니다. 실행 파일 사용자는 SDK가 필요하지 않습니다. 최초 빌드에는 NuGet 다운로드를 위한 인터넷 연결이 필요합니다.

새로 clone한 환경에서는 Windows에 .NET SDK 10.0.404와 Python을 설치하세요. `.tools` 폴더는 Git에 포함되지 않습니다. 설치 프로그램을 빌드하려면 Inno Setup 7.1.1도 필요하며, 아래 스크립트에 `-CompilerPath`로 `ISCC.exe`의 전체 경로를 전달할 수 있습니다.

```powershell
# 테스트 이미지 생성에는 Python + Pillow가 필요합니다.
python -m pip install Pillow==12.3.0

# 테스트 후 단일 EXE 생성
powershell -ExecutionPolicy Bypass -File scripts/Build.ps1

# 테스트 이미지 생성 없이 EXE만 다시 빌드
powershell -ExecutionPolicy Bypass -File scripts/Build.ps1 -SkipTests
```

실행 결과: `dist/LightImageViewer.exe`. 함께 복사되는 README와 라이선스 파일은 참고 문서이며 실행에는 EXE 하나만 필요합니다. 라이선스 내용은 EXE 내부에도 포함되어 F1로 볼 수 있습니다.

### 설치 파일 빌드 및 검증

Inno Setup 7.1.1 컴파일러를 프로젝트의 `.tools/inno`에 포터블 방식으로 준비했습니다. 다른 환경에서는 Inno Setup 7 컴파일러 경로를 `-CompilerPath`로 전달하면 됩니다.

```powershell
# 기존 dist/LightImageViewer.exe를 그대로 포장 (뷰어 EXE는 재빌드하지 않음)
powershell -ExecutionPolicy Bypass -File scripts/Build-Installer.ps1

# 격리된 테스트 앱으로 설치·재설치·제거·설정 유지/삭제 검증
powershell -ExecutionPolicy Bypass -File scripts/Test-Installer.ps1
```

설치 스크립트는 `installer/ImageViewer.iss`입니다. 설치 파일 버전은 포장하는 EXE에서 읽습니다. `dist/SHA256SUMS.txt`에는 포터블 EXE와 설치 파일의 해시가 기록됩니다. 테스트는 고유한 앱 ID와 시작 메뉴 폴더, 프로젝트 내부 설치·설정 경로를 사용하고 테스트 앱을 제거합니다. 실제 LightImageViewer 설치나 사용자 설정은 사용하지 않습니다. 검증 로그는 `artifacts/installer-tests`에 저장됩니다. 자동 검증용 패키지만 관리자 권한 없는 모드로 컴파일하여 실행합니다. 배포 설치 파일은 관리자 권한을 요구하고 공용 Program Files (x86) 경로를 사용하는지 별도 확인합니다.

소스 구조:

- `src/ImageViewer/MainWindow.xaml`: 화면 구성
- `src/ImageViewer/MainWindow.xaml.cs`: 파일 열기, 탐색, 취소/동시성, 오류 표시
- `src/ImageViewer/MainWindow.View.cs`: 확대·이동, 전체화면, 원본 교체, 주변 파일 미리 읽기
- `src/ImageViewer/MainWindow.Playback.cs`: 애니메이션 재생과 취소
- `src/ImageViewer/ViewTransform.cs`: 포인터 기준 확대와 이미지 이동 범위
- `src/ImageViewer/WindowPlacementStore.cs`: 창 상태 저장·복원
- `src/ImageViewer/ImageLoader.cs`: 메모리 캐시와 디코딩 동시성 제한
- `src/ImageViewer/AnimationSession.cs`: 애니메이션 프레임 합성과 제한된 프레임 캐시
- `src/ImageViewer/ImageCatalog.cs`: 지원 형식, 폴더 범위, 자연 정렬
- `src/ImageViewer/ImageDecoder.cs`: 디코딩, 투명도, EXIF 방향 보정
- `tests/ImageViewer.Tests`: 실제 이미지 및 WPF 창 상태를 검사하는 테스트 실행 프로그램
- `tests/create_fixtures.py`: 독립 디코더인 Pillow로 테스트 이미지 생성
